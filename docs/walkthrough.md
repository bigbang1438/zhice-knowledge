# 自己能讲清楚的项目路线

从能运行开始：设置演示密码、打开页面、导入examples中的资料，先只检索，再启用模型问答。记录一次成功和一次失败，核对回答中的每条来源。

## 建议按这个顺序读代码

1. `KnowledgeController`：请求怎样到达业务，身份从哪里来，何时做权限与输入检查。
2. `KnowledgeStore` 与schema：文档、片段、会话和回答怎样关联，哪些写入需要同一事务。
3. `DocumentParser`：文本如何切片，长行怎样处理，PDF页码与文本行号分别指什么。
4. `Retrieval`：BM25重关键词，向量看语义相近，RRF合并排名；为什么两种分数不能直接相加。
5. `KnowledgeEngine`：直接问答与工具循环哪里不同，如何限制工具参数和执行预算。
6. `OllamaGateway`：HTTP请求怎样构造，如何处理超时、响应过大、非法JSON与工具反馈。
7. 前端controller：切换资料库或会话时，如何丢弃迟到响应并保留冲突输入。

## 需要用自己的话回答的问题

- 一份文档为什么拆成片段？切得太小和太大分别会怎样？
- 检索没有找到、找到了错误片段、找到正确片段却答错，怎样分别定位？
- 向量模型更换后为什么要重新索引？
- 文档替换期间为什么不能先删除旧索引？
- 问答生成期间有人删了资料，为什么要核对修订号？
- 引用编号合法能保证回答正确吗？
- 工具调用与固定代码顺序检索有什么区别？工具里为什么没有shell或任意URL？
- 固定24题检索结果能代表所有用户问题吗？哪些失败需要保留？

这是AI辅助学习项目。应准确说明自己使用了哪些辅助、亲自理解和修改了哪些代码，避免把生成代码表述成已独立掌握全部原理。
