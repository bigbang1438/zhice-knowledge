# 架构与取舍

## 一次导入

登录会话确定操作者，服务端检查资料库成员关系；读取当前资料库修订号，验证文件大小与文件名。解析、文本分段和可选向量生成在数据库事务之外执行，避免模型慢响应长期占用数据库行锁。

真正提交时重新锁定资料库，核对修订号和原文档版本。文档、片段、向量与资料库修订号一起提交。并发更新已经先完成时，旧请求返回409；解析、模型或事务失败不删除旧版本。

PDF 页码来自 PDF 页面；行号来自提取后的页内文本，并非 PDF 视觉排版的物理行。Markdown / TXT 保留输入原文行号。扫描图像需要 OCR，此处不假装已经解析。

## 一次检索与问答

读取授权资料库的一致片段快照，再执行 BM25、余弦向量或 RRF 混合排序。向量检索要有真实嵌入模型和完整已索引向量，不用随机数、哈希向量或静默词法替代。

直接问答先检索再调用聊天模型。分步查找把 `search_knowledge(query)` 和 `read_passage(source_id)` 定义给模型；模型选择调用，服务端执行、返回反馈，再让模型继续。读取工具只接受本轮已检索片段，不能靠构造编号读取其他资料。

工具名称、参数字段和类型由服务端校验。模型轮次与工具步骤共用8步预算，总时限90秒。网络请求不跟随重定向、不走代理，只连接显式本机 HTTP 地址。没有网页、命令行、代码执行或写入工具。资料内指令不能增加服务端工具权限，但仍可能影响模型文本判断。

最终回答的引用编号必须存在于本轮来源列表；没有引用、引用越界或非法模型输出会报错。结构合法不等于语义忠实，不能将其写成“彻底消除幻觉”。

## 会话与资料变化

资料库和会话查询始终绑定实际登录用户。模型只读取当前会话最近六轮，限制历史文本长度，不做长期记忆或跨会话检索。历史中的引用不自动作为本轮依据。

模型执行期间不持有知识库锁。提交回答时重查资料库修订号与会话轮数，资料更新或删除后拒绝保存基于旧快照的回答。界面保留问题供用户核对后重试。已经保存的历史回答是当时的记录，其引用正文仍为旧快照，不能当成现行政策。

## 有意保留的限制

- H2 存储向量，Java 对最多2,000片段做精确余弦计算；没有 ANN、大规模索引或横向扩容。
- 更换嵌入模型需要重新索引；维度检查无法识别同维度不同模型，操作时应新建演示库或重新导入资料。
- 默认是本机演示账号，不提供注册、组织邀请和完整管理员后台。
- 回答接口当前一次返回完整回答；页面提供等待状态，没有伪装成逐字模型流式输出。
- 固定检索集与真实聊天模型分开记录；不以小样本结果推导陌生领域问答准确率。
