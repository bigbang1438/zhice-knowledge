## 固定检索集

[问题与金标准](../evaluation/questions.json)包含 20 个可回答问题、4 个资料外问题。语料是 [examples](../examples/) 中 4 篇原创虚构短文，本次导入共 **4 个片段，每篇全文只有 1 个片段**。因此这里主要测量四份短文之间的排序，没有检验长文分段、复杂证据定位或生产规模检索。

使用真实本地 BGE-M3 嵌入向量，比较 BM25、余弦向量排序和 RRF 混合排序。相关性判断为“文件名符合金标准，且返回片段包含指定原文短语”；它不是人工标注的语义相关性或模型回答评分。指标仅对 20 个可回答问题计算：

| 模式 | 首位命中 / Recall@1 | Recall@3 | MRR@5 | 资料外问题返回空结果 |
| --- | ---: | ---: | ---: | ---: |
| BM25 | 20/20（1.000） | 1.000 | 1.000 | 0/4 |
| 向量 | 19/20（0.950） | 1.000 | 0.975 | 0/4 |
| 混合 | 20/20（1.000） | 1.000 | 1.000 | 0/4 |

向量检索的 `q15` 首个相关片段位于第 2 名，此结果保留在[逐题报告](../evaluation/retrieval-report.json)。三个模式对 4 个资料外问题都返回了候选资料，**没有实现可靠的无答案识别**。正余弦值、词项重合及 RRF 排名都不能证明资料足以回答问题；本次没有为得到好看的结果而调整阈值或删除失败题。

这些是公开、固定、由项目作者编写的小样例，不是盲测、留出集或通用准确率。BM25 和混合在本例同为满分，不能据此断言混合检索更优。下一步应增加独立编写的长文、相近政策与资料外问题，再划分校准集和测试集。

公开报告保留每次返回的来源标识、文件、页码、行号、分数、原文 SHA-256、金标准匹配结果、名次及耗时，用哈希替换重复正文；正文可以在示例文件核对。当前报告由实际 HTTP 运行结果压缩而来，记录了原始报告 SHA-256，未重新请求模型、修改指标或隐藏失败。报告中的毫秒级耗时也不是负载测试。

## 真实模型观察

使用本地导入的 `zhice-qwen3-4b` 聊天模型与 `zhice-bge-m3` 嵌入模型，在上述 4 篇短文上运行 6 个预先列出的案例。完整最终回答、来源、公开工具记录和失败均保存在[真实模型记录](real-model-observations.json)。

| 案例 | 模式 / 检索 | HTTP | 可见结果 | 耗时 |
| --- | --- | ---: | --- | ---: |
| r01 | RAG / 混合 | 201 | 回答周会为周三下午三点，附 `[1]` | 13.94 秒 |
| r02 | RAG / 向量 | 201 | 回答自定义标签上限为十二个，附 `[1]` | 9.55 秒 |
| r03 | RAG / 混合 | 201 | 追问标签名称是否能重复，回答不能，附 `[1]` | 13.45 秒 |
| a01 | Agent / 混合 | 201 | 回答删除任务后十四天内可恢复；调用 1 次 `search_knowledge` | 24.59 秒 |
| a02 | Agent / BM25 | 201 | 回答附件大小与数量限制；调用 1 次 `search_knowledge` | 35.80 秒 |
| n01 | RAG / 混合 | 502 | `MODEL_THOUGHT_BOUNDARY`，未返回答案 | 27.86 秒 |

两个 Agent 案例确实调用了检索工具，但都只调用一次；它们没有实测 `read_passage` 的模型选用，也不能证明复杂多步规划能力。`r03` 是带前文主题的追问，不能当作独立无上下文问答样本。

`n01` 是“海豚的声呐频率是多少赫兹”，资料中没有答案。该次响应未满足最终答案边界，系统以 502 安全失败；它不是成功回答，也不是检索返回空结果后的 `insufficient`。不能将它计为无答案识别成功。成功案例的关键词和引用检查仍需人工复核，引用编号合法并不保证每句话都忠实于来源。

### 旧模板兼容边界

真实调用发现，已导入的旧 Qwen3 模板会预先打开分析段，导致 `think:false` 仍把分析前缀放进正文。修复采用显式配置与失败关闭：

- 默认 `ZHICE_THOUGHT_IN_CONTENT=false`，正文出现完整或截断的分析标记时拒绝响应。
- 仅对核对过的旧模板启用 `true`：文本答案必须有且只有一个完整 `</think>` 结束标记；丢弃之前全部内容，只返回非空最终答案。重复、截断、顺序错误的标记会失败。
- 对已验证结构的原生工具调用，兼容模式丢弃全部伴随正文，只保留受限工具参数。

新增 4 项 HTTP 回归测试先复现失败，再验证上述边界。公开案例只保留最终答案或安全错误，不发布分析正文。此适配针对已核对的模板格式，不能替代模型协议适配或语义审核。

## 复现检索

按[运行说明](../README.md)启动本机应用和聊天、嵌入模型。使用单独演示数据库和仅包含 4 篇示例的资料库；脚本会导入缺少的示例，并检查文档数、片段数和来源文本哈希。不要指向含个人资料的数据库。

```powershell
$env:ZHICE_EVAL_PASSWORD = Read-Host '输入本机演示账号密码'
python evaluation/run_retrieval.py --output evaluation/retrieval-report.json
```

脚本只访问 `http://127.0.0.1:8093`，不使用代理或跟随重定向；密码来自环境变量，不写入报告。新运行直接产生相同的紧凑格式。既有原始 HTTP 报告还可以离线压缩，无需密码或网络：

```powershell
python evaluation/run_retrieval.py --compact-existing raw-report.json --output compact-report.json
```

更换嵌入模型后应重新导入文档。同维度的不同模型也不能混用旧向量。复现时模型版本、运行设备、随机生成、文档版本及已有数据都会影响结果，不应要求重现相同的耗时或 UUID。
